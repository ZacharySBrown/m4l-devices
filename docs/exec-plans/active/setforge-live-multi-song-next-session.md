## What needs doing next

### Critical: loader.js resolution in Live

The `.amxd` references `loader.js` by filename but doesn't embed it. When Live loads the `.amxd`, Max can't find `loader.js` unless it's in Max's search path.

**Current workaround:** Copy `loader.js` to `~/Documents/Max 8/Library/` and/or the Live set directory. This was done for the current session but needs to be automated.

**Proper fix options (pick one):**
1. Modify `amxd_pack` to embed `loader.js` inside the `.amxd` binary
2. Add a build step that copies `loader.js` to `~/Documents/Max 8/Library/` after every build
3. Use Max's `project.searchpath` with an absolute path (already attempted, didn't help)
4. Freeze the device in Live after loading (manual step)

### syncFromLive short-clip bug

The sync reads clip markers from Live and computes sample times. For short clips (1-2 bar drums), `length_sec` comes back as 0 in some cases. The fix using BPM-derived `secPerBeat` from warp markers is in the code but needs hardware verification.

The issue: when a clip has only 2 warp markers at similar positions, the `secPerBeatFromMarkers` calculation may be inaccurate. The fallback to manifest BPM should handle this, but the data shows `length_sec=0` persisting for drums.

**Debug approach:** Send `sync` command, then `inspect`, check `/tmp/setforge_inspect.json` to see what Live actually reports for the clip properties vs what the sync produces.

## Architecture summary

```
IAC MIDI → [setforge-grid.amxd] → send sf-grid-in → [setforge-loader.amxd]
                                                          ↓
                                                    [js loader.js]
                                                     inlet 0: MIDI
                                                     inlet 2: messages + UDP
                                                          ↓
                                              handleNoteOn → handleGrid1Press
                                                          ↓
                                    ┌─────────────────────┼─────────────────────┐
                                    │ rows 1-4: stems     │ rows 5-6: presets   │
                                    │ (chop fire)         │ (activate/stage)    │
                                    │                     │                     │
                                    │ row 7: modifiers    │ row 8: scenes       │
                                    │ (SOLO=per-row)      │ (save/recall)       │
                                    └─────────────────────┴─────────────────────┘
                                                          ↓
                           8 audio tracks: sf-drums, sf-bass, sf-other, sf-vox
                                          sf-drums-y, sf-bass-y, sf-other-y, sf-vox-y
```

**Four views:** solo → per-row (double-tap SOLO) → dual-song (top-right side) → control (top-left side)

**Key functions:**
- `getEffectivePreset(stem)` — central indirection for per-row mode
- `loadStemClipsToTrack(stem, presetIdx, offset, trackPath)` — single-stem clip loader
- `onDualSongChopPress(row, col)` — routes to X or Y tracks
- `syncFromLive()` / `fullSave()` — round-trip clip state
- `pollCommandFile()` — reads /tmp/setforge_cmd.txt for remote commands

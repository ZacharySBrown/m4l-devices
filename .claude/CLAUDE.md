# m4l-devices

Boutique-pedal-style M4L audio effect devices, built spec-first and
mostly autonomously via the agent harness at `~/raindog/harness`.

## Architecture

```
m4l-devices/                    ← this repo (one folder per device)
└── tape-loss/
    ├── tape-loss.amxd          ← compiled device
    ├── tape-loss.maxpat        ← source patch (uncompressed JSON)
    ├── ...

specs/                          ← spec-first authoring
├── tape-loss-spec.md           ← prose spec (author-readable)
└── tape-loss.pedal.yaml        ← structured DSL extracted by pedal-architect

docs/                           ← generated by `forge-device analyze`
├── design-docs/<name>-design.md
├── design-docs/dsp/<module>-design.md   ← DSP specialist's algorithm docs
└── exec-plans/active/<name>-build.md    ← phased plan with manual-step callouts
└── exec-plans/active/<name>-audit.ndjson ← live audit trail
```

The build tooling itself (Python orchestrator, `.amxd` packer, verifiers,
audit emitter) lives in the harness quickstart at
`~/raindog/harness/quickstarts/max-plugin/tools/`. This repo invokes it
via `PYTHONPATH`.

## How to forge a device

```bash
# 1. Author or extract a structured spec (pedal-architect's job)
#    specs/<name>.pedal.yaml

# 2. Run analyzer end-to-end (emits design doc + exec plan + audit start)
PYTHONPATH=$HARNESS_TOOLS python3 -m forge_device analyze \
    specs/<name>.pedal.yaml --repo-root .

# 3. Review the plan + Manual Steps Required block
cat docs/exec-plans/active/<name>-build.md

# 4. (Future: Phase 2 build) — generate per-module patches, pack .amxd
#    Currently: pedal-engineer hand-implements modules using
#    stemforge_bridge.patcher primitives, runs verifiers per artifact.

# 5. Inspect audit trail
PYTHONPATH=$HARNESS_TOOLS python3 -m forge_device summary \
    docs/exec-plans/active/<name>-audit.ndjson
```

`$HARNESS_TOOLS` should be `~/raindog/harness/quickstarts/max-plugin/tools`.
Add to your shell rc or set per-invocation.

## Personas (loaded from harness via symlinks)

`.claude/agents/` symlinks point at the harness's pedal-* personas:

- **pedal-architect** — strategic. Reads spec, decides zone placement,
  produces design doc + exec plan with explicit manual-step callouts.
- **pedal-dsp** — signal-processing specialist. Owns filter design,
  waveshaper math, modulation topologies. References RBJ Audio EQ
  Cookbook + JOS textbooks at `~/raindog/harness/references/`.
- **pedal-engineer** — platform plumbing. Generates `.maxpat` JSON via
  bridge primitives, packs `.amxd`, runs verifiers, emits audit.

## Skills

`.claude/skills/` symlinks point at:

- **/forge-device** — orchestrates spec → design → plan → build → verify
- **/forge-telemetry** — drives a running device headlessly via UDP

## Verifiers (the code-as-harness layer)

The harness encodes the 20 hard-won M4L pitfalls as verifier functions in
`tools/forge_device/verifiers.py`. Every build artifact runs through
them automatically. New pitfalls discovered during development MUST get
a verifier added before the fix is shipped — that's how the harness
evolves.

See `~/raindog/harness/quickstarts/max-plugin/docs/architecture/code-as-harness.md`
for the architectural frame (after Murphy et al. arXiv:2603.03329).

## Conventions

- **Spec first.** Every device has both a prose spec (`specs/<name>-spec.md`)
  and an extracted DSL spec (`specs/<name>.pedal.yaml`). The architect
  produces the DSL from the prose.
- **Audit always.** Every `forge-device` run writes to
  `docs/exec-plans/active/<name>-audit.ndjson`. Don't disable.
- **No hand-wired `.maxpat`.** Use `stemforge_bridge.patcher` primitives.
- **Verify before ship.** All `PATCHER_VERIFIERS` and `AMXD_VERIFIERS`
  must pass.
- **Manual steps explicit.** Plans have a `## Manual Steps Required`
  block. Aim for ≤30 seconds of human time per build cycle excluding
  the optional IR-capture phase.
